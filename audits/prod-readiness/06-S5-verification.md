## Bug Found and Fixed

### ISSUE-S5-01 — `getMySchoolRating` wrong response shape → "Muassasa topilmadi"

**File:** `backend/controllers/parent/parentSchoolRatingController.js:128-135`

**Root cause:** `GET /parent/school-rating` returned `{ schoolId, schoolName }` (two primitive fields) but
`TeacherRating.jsx:80-81` reads `schoolRatingData.school` (an object) to get `school.id` for the
POST payload and school display. Because `school` was `undefined`, the state was `null` →
the school section rendered "Muassasa topilmadi" (not found) permanently.

Additionally, `summary: { average, count }` was absent from the response — the frontend
fell back to `{ average: 0, count: 0 }` on every load.

**Fix (commit 6d9d5f3):**
```js
// Old:
data: { rating: ..., schoolId: child.schoolId, schoolName: school?.name ?? null }

// New:
data: {
  rating: rating ? rating.toJSON() : null,
  school: school ? { id: school.id, name: school.name } : null,
  summary: { average, count },  // computed from SchoolRating.findAll
}
```

**Tests added:** 4 new tests in `parentSchoolRatingController.test.js`:
- Response shape: `school` object, `rating`, `summary` all present
- Empty-children early return
- 404 on childId-not-found
- **Revert-test:** asserts `schoolId` and `schoolName` are absent from new response

Pre-existing test in `parentSchoolRating.test.js` updated to match new shape.

**Deployed to Railway:** 6d9d5f3. Verified live: `school: { id, name }`, `summary: { average: 4.3, count: 12 }`.

**Route note discovered:** Parent rating is at `/rating` (singular), not `/ratings`. Child profile is at `/child`, not `/child-profile`. Tests used correct paths after correction.
